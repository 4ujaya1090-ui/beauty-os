# ARCHITECTURE

## Главная идея

Beauty OS — это не набор страниц.

Beauty OS — это система, построенная вокруг сущностей.

Интерфейс лишь отображает данные.

Вся логика строится вокруг объектов системы.

# Основной принцип

Каждая сущность хранится только в одном месте.

Пример.

Правильно:

Appointment
    procedureId

Procedure
    name
    price
    duration

Неправильно:

Appointment
    procedureName
    duration
    price

Данные не должны дублироваться.

---

# Firebase

Источник данных.

Никаких локальных массивов после подключения Firebase.

---

# Принципы разработки

1.
Сначала архитектура.

Потом код.

2.
Каждый модуль независим.

3.
Максимальное переиспользование компонентов.

4.
Никакого копирования логики.

5.
Любая новая функция должна вписываться в существующую архитектуру.

6.
Одна ответственность — один компонент.

7.
Сначала модель данных.

Потом интерфейс.

Никогда наоборот.

# Масштабирование

Архитектура должна позволять добавить:

новые роли

новые процедуры

новые услуги

новые кабинеты

новые филиалы

новые языки

новые страны

без переписывания существующего кода.
