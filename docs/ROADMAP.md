# Beauty OS — Roadmap

## Готово

**Специалист**
- [x] Клиенты — полный CRUD, поиск, медкарта с настраиваемыми подписями полей
- [x] Прайс-лист (процедуры) — CRUD
- [x] Календарь и запись на приём — создание, редактирование, удаление, защита от пересечений по времени
- [x] Бонусы клиентам — ручное начисление/списание
- [x] Статьи (дневник специалиста) — черновик/публикация
- [x] Профиль специалиста — имя и специализация вместо хардкода
- [x] График работы — настраивается, используется при самозаписи клиента
- [x] Вход по email/паролю (Firebase Auth)
- [x] Данные в Firestore — не пропадают при обновлении страницы

**Клиент**
- [x] Отдельный вход (специалист создаёт логин из карточки клиента)
- [x] Личный кабинет — бонусы, ближайшая запись, история
- [x] Самостоятельная запись на приём — с учётом графика специалиста и занятых слотов
- [x] Просмотр опубликованных статей специалиста

**Инфраструктура**
- [x] Firestore Security Rules — доступ разделён по ролям
- [x] Публикация (Firebase Hosting) — доступно по ссылке с любого устройства
- [x] PWA — устанавливается на телефон как приложение, свой значок

## В планах, но сознательно отложено

- [ ] **Фото "до/после"** — требует Firebase Storage, тот, в свою очередь, требует платный тариф Blaze. Ждёт решения.
- [ ] **Синхронизация статей с Telegram-каналом** — требует бэкенд (Cloud Functions или аналог), тоже упирается в Blaze.

## Известные ограничения (не баги, осознанный выбор)

- Один специалист в системе. Данные не разделены по `specialistId` — решение принято сознательно, чтобы не проектировать многопользовательскую архитектуру под несуществующего второго специалиста. Если такой человек появится реально — это отдельная, спланированная переработка.
- Клиент не может отменить или перенести свою запись сам — только специалист.
- Комментарий специалиста к записи технически доступен на чтение клиенту через Firestore напрямую (не через интерфейс) — минорный риск, отдельная переработка при необходимости.

## Не начато

- [ ] Отмена/перенос записи клиентом
- [ ] Роль "Гость" — публичная страница о сервисе без входа
- [ ] Ваучеры/сертификаты — не обсуждали конкретику
- [ ] Роль администратора как отдельный вход — решили, что не нужна: владелец использует тот же доступ специалиста под отдельным логином
