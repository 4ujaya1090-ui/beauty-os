# Beauty OS — Карта экранов

Два независимых дерева экранов — по роли. Роль определяется автоматически при входе (см. ARCHITECTURE.md), отдельного выбора роли на экране входа нет.

---

## Роль: Специалист

```
Вход
  │
  ▼
Главная (/)
  ├── Настройки (/settings/schedule) — график работы + подписи карты клиента
  ├── Записать (быстрое действие) ──▶ /appointment
  ├── Календарь (/calendar) ──▶ /appointment (редактирование по клику)
  ├── Прайс (/procedures)
  ├── Клиенты (/clients)
  │     └── Карточка клиента (/client)
  │           ├── Медкарта (сохраняется на месте)
  │           ├── Создать вход для клиента
  │           ├── История процедур (редактирование/удаление записи)
  │           └── Удалить клиента
  ├── Новый клиент (/new-client)
  ├── Статьи (/articles)
  │     ├── Новая публикация (/articles/new)
  │     └── Просмотр (/article) ──▶ Редактировать (/edit-article)
  └── Выйти
```

## Роль: Клиент

```
Вход
  │
  ▼
Кабинет (/)
  ├── Записаться на приём (/my/booking)
  │     процедура → дата → свободное время → подтверждение
  ├── Мои записи (/my/appointments) — все предстоящие
  ├── История посещений — прямо на главном экране кабинета
  ├── Статьи специалиста
  │     ├── /my/articles — полный список (только опубликованные)
  │     └── /my/article — чтение одной статьи
  └── Выйти
```

Клиент не видит: других клиентов, чужие имена в записях, черновики статей, настройки, медкарту (даже свою — её видит и правит только специалист).

## Роль: Гость

Не реализована. Прямого адреса приложения без входа не существует — сразу экран логина. Публичной посадочной страницы ("что это за сервис") нет.

## Экраны, которые ещё не построены

- Регистрация — новых клиентов заводит только специалист (осознанное решение, не пробел)
- Отмена/перенос записи самим клиентом
- Загрузка своего фото у клиента, фото "до/после" у записи — ждут решения по Firebase Storage
- Публичная страница о сервисе для гостя
